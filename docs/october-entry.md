## 要解决的问题

Agent 的工具调用可能出现结果缺失、失败后继续写入、重试过多或重复执行副作用。模型回复和普通日志难以直接表达这些跨事件约束，也不容易稳定地放进 CI 回归。

## 项目方案与已有基础

MoonAgentCheck 用 MoonBit 实现确定性行为评估器：接入方将 Agent 记录转换为事件，库按 `call_id` 关联单次调用、按 `operation_id` 识别同一业务操作，并返回带规则码和事件索引的违规结果。核心检查离线运行，不连接模型、网络或真实工具。

仓库已有公开的 `0.2.0` 版本，包含核心规则、稳定违规码、场景回归、策略门禁、结构化报告、轨迹工具，以及 Python 和 Responses 离线适配示例。十月工作以此为基线，不重复计算此前成果。

## 三个可复现场景

| 场景 | 关键事件 | 预期检查结果 |
| --- | --- | --- |
| 数据分析后导出报告 | `read_csv` 调用与成功结果；随后 `write_csv` 调用、成功结果和完成事件 | 调用、结果与写入按各自 `call_id` / `operation_id` 配对，轨迹通过 |
| 仓库助手应用补丁 | 同一 `operation_id` 的两次 `write_file` 调用都成功并各自完成 | 第二次完成被识别为重复副作用（`duplicate-side-effect` / `AGC004`） |
| 工单助手更新回复 | `update_ticket` 结果未知或关联字段与原调用不一致，却继续报告写入完成 | 轨迹不得通过；报告未知结果或关联不一致，并拒绝无成功结果的写入 |

## 十月新增目标

Responses 输出序列可能同时包含消息、推理内容和函数调用。本期扩展现有适配器：明确跳过 `message` 与 `reasoning`，保持工具调用和结果的原始顺序；对未支持的项目类型报告映射问题及其输入索引，不静默忽略。这样可避免把普通内容误判为工具行为，也避免不完整接入被报成通过。

## 验收方式

以 MoonBit 回归用例和 Python 离线 fixture 验证混合输出、调用结果关联及未支持类型；通过现有 CI 运行格式检查、构建、检查、测试和示例。示例使用公开字段形状，不含真实用户数据，也不依赖模型密钥或网络。开发者确定项目目标、规则边界和验收结论，AI 工具辅助实现、测试用例整理和文档校对，最终成果由开发者复核并负责。
