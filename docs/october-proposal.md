## 项目简介

Agent 的工具调用可能出现结果缺失、失败后继续写入、重试过多或重复执行副作用。普通日志能记录发生了什么，却不容易表达跨事件约束，也难以稳定地放进 CI 回归。

MoonAgentCheck 使用 MoonBit 实现确定性行为评估器。接入方把 Agent 记录转换成事件，评估器按 `call_id` 关联调用与结果、按 `operation_id` 识别同一业务操作，并返回可复核的规则码与事件位置。核心检查离线运行，不连接模型、网络或真实工具。

## 十月目标与可复现示例

本期扩展 Responses 输出适配：保留工具调用与结果的顺序，明确处理消息、推理内容和未支持条目；对无法完整映射的记录给出索引诊断，避免静默跳过后误报通过。

- **数据分析后导出报告：**读取与写入调用、结果正确配对，完整轨迹通过。
- **仓库助手应用补丁：**同一业务操作重复完成写入，报告 `duplicate-side-effect`（`AGC004`）。
- **工单助手更新回复：**结果未知仍报告完成时，报告 `unknown-result`（`AGC018`）并关闭通过状态；关联不一致也会单独报告。

示例使用公开字段形状，不含真实用户数据，可离线重复运行。

## 项目基础、验证与价值

项目已有 MoonBit 核心评估器、89 个 MoonBit 回归测试、5 个 Python 离线对照 fixture 和 GitHub Actions 自动验证。项目通过 Mooncakes 发布 `0.2.0`；十月分支上的新实现以未发布的 `0.3.0` 开发线记录，不混同于已发布包。

项目补充 Agent runtime、workflow 与 telemetry 之后的行为验证环节，用可重复的规则检查工具调用顺序、失败处理和副作用约束。它不运行 Agent、不接管工具权限，也不替代权限沙箱。

**复核方式：**通过 MoonBit 格式检查、构建与测试，运行离线场景 fixture，并查看 GitHub Actions。相同输入应得到相同规则码、事件位置和结论。
