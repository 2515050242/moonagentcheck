# 决策记录 0003：多场景回归必须传递完整策略

## 背景

单条轨迹已有 `evaluate_with_policy`，可同时执行重试上限和工具 allowlist。原有的场景、目录与 `SuiteRunner` 接口却只向评估器传递 `max_retries`。这使调用者在回归运行中声明的只读或严格策略丢失工具权限部分，和单条轨迹的结果不一致。

## 决策

新增 `evaluate_scenarios_with_policy`，并让目录、质量门禁和运行器的策略入口调用它。旧的只带 `max_retries` 的 API 保留为兼容包装：它们构造没有 allowlist 的策略。每个场景独立复用同一不可变策略，继续保持输入顺序、场景名称和既有稳定违规码。

## 取舍

不引入策略 DSL、外部权限服务或 Agent runtime；`EvaluationPolicy` 仍只是调用者已知的离线规则配置。这样修复的是实际可调用回归路径的一致性，并通过允许与拒绝场景、按标签运行和单条运行的回归测试锁定边界。
